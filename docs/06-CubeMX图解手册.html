1. 先建立三个概念，否则按哪里都记不住

你现在的状态不是“不会点按钮”，而是不知道为什么点。三个概念立住，界面就自己变得可读了。

概念一：CubeMX 是“配置器”，不是 IDE

它不写业务代码，也不烧录。它干的事只有一件：把你选的外设和参数，翻译成一堆初始化函数（MX_I2C1_Init、MX_TIM3_Init…）和一份工程文件。真正的业务（采样、FFT、显示）写在别处，跟它没关系。

概念二：它只生成“初始化”，不管“跑起来”

这是最容易误解的地方。MX_TIM3_Init 只负责把 PSC、ARR 写进寄存器，它不会启动定时器、也不会开中断。启动是 HAL_TIM_Base_Start_IT()，开中断是 HAL_NVIC_EnableIRQ()，这两个调用没有 GUI 按钮，只能写代码——所以这个工程的 sampler.c 里才有那几行。

概念三：手写代码只能写在 USER CODE 区里

生成的文件里到处是这种注释对：

/* USER CODE BEGIN xxx */
   ... 你写的东西 ...
/* USER CODE END xxx */

两块注释之间的内容，CubeMX 重新生成时会原样保留；注释外面的一切都会被覆盖。这就是为什么“改了 CubeMX 之后代码没被冲掉”。

4. 七个操作：点哪里、改什么、改完看到什么

这个工程从头到尾只用了七次“配置动作”。下面每个都配了现场截图，截的是你这个工程的当前状态——所以有些图里会看到“和标准做法不一样”的地方，那些正是第 5 节要讲的。

操作 1｜System Core → SYS：先保住下载口

System Core 展开后的目录。1SYS 在这里；2RCC 在它下面。注意 SYS 前面有绿勾、RCC 没有——绿勾就是“这个外设被改过”的记号。
  • 点哪里：左侧 System Core → SYS。
  • 改什么：Debug 从 Disabled 改成 Serial Wire。
  • 为什么必须先做：F407 的 PA13/PA14 是 SWD 下载口。CubeMX 默认把它当普通 IO，一旦固件跑起来把这两根脚配成别的功能，下一次就下载不进去（锁芯片）。先占住 SWD，是每个 F4 工程的第一条纪律。
  • 改完看到：SYS 出现绿勾；芯片图上 PA13/PA14 变成绿色并被标成 SYS。

你可以点开 SYS 面板核对 Debug 那一栏是不是 Serial Wire——这一项截图里我没抓到面板细节，别当成已确认。

操作 2｜System Core → RCC：告诉芯片“晶振从哪来”

RCC 面板现状：1High Speed Clock (HSE) = Disable，LSE 也是 Disable。也就是说这块板子的外部晶振，这个工程根本没用。
  • 点哪里：System Core → RCC。
  • 三个选项的含义：Disable＝不用外部晶振；Crystal/Ceramic Resonator＝板上焊了石英晶体（绝大多数核心板是这种）；BYPASS Clock Source＝外部直接送进来一个有源时钟信号（几乎不用）。
  • 这一步的现状：Disable。所以整个工程跑在芯片内部的 HSI 16MHz 上，精度 ±1%。这不是错，是取舍——代价是采样率实际是 1000±10Hz。要换 HSE，改这里 + 改时钟树两处，第 7 节给了顺序。
  • 改完看到（如果改成 Crystal）：RCC 出现绿勾，芯片图上 OSC_IN/OSC_OUT 变绿，时钟树里 HSE 那格从灰变亮。

操作 3｜Connectivity → I2C1：把两根线配成 I2C

I2C1 的 Parameter Settings：1I2C Speed Mode = Standard Mode；2I2C Clock Speed (Hz) = 100000。这就是 100kHz，不是 400kHz。
  • 点哪里：Connectivity → I2C1（或用搜索框输 I2C1 回车）。
  • 改什么：I2C 模式（不是 I2C 从机、也不是 SMBus）；Speed Mode 选 Standard/Fast；填时钟频率。
  • 这个工程的现状：标准模式 100kHz。而运行时代码里把它改成了 400kHz（下一节给原文）。所以答辩被问“你 I2C 跑多少”，正确答案是 400k，但 .ioc 里写的是 100k——这个不一致必须自己先讲出来，别等老师翻出来。
  • 改完看到：I2C1 绿勾，芯片图上 PB8/PB9（或 PB6/PB7，取决于你选的那组）变绿。
顺手记一下地址。这条总线挂两个从机：MPU6050 = 0x68，SSD1306 OLED = 0x3C。地址是器件定的，CubeMX 不管，代码里写死。这两组数在答辩里属于“必须张口就来”的。

操作 4｜Timers → TIM3：配出 1kHz 的采样节拍

TIM3 的 Mode 和 Counter Settings：1Clock Source = Internal Clock；2Prescaler = 83；3Counter Period = 999，Counter Mode = Up。
  • 点哪里：Timers → TIM3。
  • 三个数字怎么来的：TIM3 挂在 APB1 上，APB1 分频≠1 时定时器时钟自动×2 = 84MHz。
    84MHz ÷ (83+1) = 1MHz（这就是 PSC 的作用：先降频）
    1MHz ÷ (999+1) = 1kHz（这就是 ARR 的作用：数够 1000 个数溢出一次）
  • 所以 PSC/ARR 不是拍出来的：它们是“从目标频率倒推”的结果。会倒推，这一项就稳了；背 83/999 没用。
  • 为什么 Timers 里选 TIM3 而不是 TIM2：因为要占一个“基本定时器”当节拍源，TIM2 可能被别的用途占了（这里是留白）。选哪个不影响 1kHz，影响的是中断向量名（TIM3_IRQHandler）。
同一个 TIM3 的 NVIC Settings 子页：1TIM3 global interrupt 这一行；2Enabled 列的方框是空的——中断没在 CubeMX 里打开。
这是本次翻出来的第二个“代码补配置”。按标准做法，这里应该勾上，勾了之后 CubeMX 会自动生成 NVIC 配置和中断入口。这个工程没勾，所以这两件事都是手写的（原文见下一节）。效果一样，但“配置里没勾、代码里开了”是老师最容易抓的点——你要么能解释（“中断使能放在业务层统一起停，便于 start/stop”），要么现在就补勾。

操作 5｜Clock Configuration：把 16MHz 推到 168MHz

时钟树关键三处：1PLL Source Mux 选中的是 HSI（HSE 那格是灰的，因为操作 2 里它是 Disable）；2PLLM = /16；3PLLN = ×336，后面 PLLP = /2、PLLQ = /7。
  • 怎么算的：16MHz ÷ 16 = 1MHz（PLL 的参考频率必须落在 1~2MHz，这是 F4 的硬约束）→ 1MHz × 336 = 336MHz（VCO）→ /2 = 168MHz（SYSCLK，F407 上限）→ /7 ≈ 48MHz（给 USB/SDIO）。
  • 下面那排分频：AHB /1 → HCLK 168MHz；APB1 /4 → PCLK1 42MHz；APB1 定时器 ×2 → 84MHz（就是操作 4 里那个 84）；APB2 /2 → 84MHz，APB2 定时器 168MHz。
  • 这个页面的用法：绝大多数格子不用碰，只在 HCLK 那一格直接输入 168 然后回车，CubeMX 会自己把所有分频凑出来（常显示“Resolve Clock Issues”变灰即无冲突）。
  • 为什么这里和 HSE 有关系：源在 HSI 时 M 必须是 16（16MHz→1MHz）；换成 HSE 8MHz 时，源要拨到 HSE、M 要从 16 改成 8（8MHz→1MHz），后面的 N/P/Q 一个都不用动——因为 8/8=1 和 16/16=1 在 PLL 之后完全重合。

操作 6｜Project Manager：定“生成到哪、用什么 IDE”

Project Settings：1Project Name = VibrationMonitor；2Project Location = C:\Users\hs\Doubao\chats\2026-11-13\new-chat-2；3Toolchain / IDE = MDK-ARM，Min Version V5.32。
  • 三个容易搞混的格子：Project Name 是工程名；Project Location 是父目录；下面 Toolchain Folder Location 才是真正的落盘目录——它是“Location + Name”拼出来的，不能单独改。
  • Toolchain 为什么选 MDK-ARM：因为你电脑上装的是 Keil（D:\Keil5），CubeMX 生成的 .uvprojx 能直接被 Keil 打开。选错这一项，Keil 里就没有工程文件可开（SW4STM32 会生成另一套）。
  • Linker Settings：Heap 0x200、Stack 0x400。FFT 用 1024 点浮点数组如果是局部的，栈要够；这个工程把缓冲放静态区，所以 0x400 够用。
  • Mcu and Firmware Package：STM32Cube FW_F4 V1.28.3，勾了 Use latest available。版本决定 HAL 的行为，写文档时要记下来。

操作 7｜Code Generator：决定“重新生成会不会毁掉你的代码”

Generated files 四个选项的实际状态（自上而下）：①Generate peripheral initialization as a pair of '.c/.h' files per peripheral 未勾；②Backup previously generated files when re-generating 未勾；③Keep User Code when re-generating 已勾；④Delete previously generated files when not re-generated 已勾。
选项这个工程的状态直接后果
per-peripheral 的 .c/.h未勾所有 MX_xxx_Init() 都写在 main.c 里。所以你以后要在 Keil 里找 I2C 初始化，只能在 main.c 找，不在 i2c.c。
Backup 旧文件未勾重新生成时不会留 .bak。没有 git 就别点 GENERATE CODE。
Keep User Code已勾关键保命项：USER CODE 段的内容重生成时保留。没勾的话，你手写的全部会没。
Delete 未再生成的文件已勾你在 CubeMX 里取消某个外设后，对应的生成文件会被删。如果你手写过 tim.c 之类放在生成目录，会被误删——所以业务代码放在 Src\App\ 下是对的。
七个操作一句话串起来：保住 SWD（操作1）→ 定晶振来源（操作2）→ 配两条通信线 I2C（操作3）→ 配采样节拍 TIM3（操作4）→ 把时钟推到 168MHz（操作5）→ 定生成到哪、给哪个 IDE（操作6）→ 定重生成规则（操作7）→ 点 GENERATE CODE。

5. 这个工程有四处“CubeMX 没做、代码补的”

这一节是整份手册里最该先看的部分。它回答一个很容易被问倒的问题：“你这工程到底是不是 CubeMX 配出来的？”答案：主体是，但有四处是代码补的，而且每一处都能说清原因。

#CubeMX 里的样子代码里补的怎么解释（答辩口径）
1RCC → HSE = Disable（图 04）整个工程用 HSI 16MHz + PLL，SystemClock_Config 里是 RCC_OSCILLATORTYPE_HSI“没有确认板上晶振起振，先用内部 HSI 保证能跑；±1% 的误差对 44Hz 带宽的振动信号不影响判定，换 HSE 只改源和 PLLM=8。”
2I2C1 = 100000（图 05）main.c 的 USER CODE I2C1_Init 2 里二次初始化成 400kHz“100k 刷一屏 OLED 要约 90ms，会闪；CubeMX 里改好需要重新生成，会动到已调好的工程，所以在 USER CODE 段里覆盖，改一处不影响别的。”
3TIM3 的 NVIC 未勾（图 07）sampler.c 里手写 HAL_NVIC_SetPriority + EnableIRQ，并自带 TIM3_IRQHandler“中断的起停在业务层统一管（Start/Stop 成对），不放在初始化里；代价是中断入口要自己写，好处是采样模块可以整体开关。”
4per-peripheral .c/.h 未勾（图 10）所有 MX_xxx_Init 都在 main.c“Basic 结构，初始化集中在 main.c，业务按模块拆到 Src\App\，读起来是一条线：main → 采样 → 处理 → 显示。”

两处代码原文（面试/答辩可以直接指着念）

① I2C 从 100k 覆盖成 400k（Src\main.c，CubeMX 生成的值在第 346 行，覆盖在 USER CODE 段里）：

  hi2c1.Init.ClockSpeed = 100000;          /* ← CubeMX 生成的就是这个 */
  ...
  /* USER CODE BEGIN I2C1_Init 2 */
  /* fast mode 400kHz: needed for the OLED refresh, otherwise one full
     screen update takes ~90ms at 100kHz and the display flickers */
  hi2c1.Init.ClockSpeed = 400000;
  hi2c1.Init.DutyCycle = I2C_DUTYCYCLE_2;
  if (HAL_I2C_Init(&hi2c1) != HAL_OK) { Error_Handler(); }
  /* USER CODE END I2C1_Init 2 */

② TIM3 中断自己开、入口自己写（Src\App\sampler.c）：

  HAL_NVIC_SetPriority(TIM3_IRQn, 1, 0);
  HAL_NVIC_EnableIRQ(TIM3_IRQn);
  if (HAL_TIM_Base_Start_IT(&htim3) != HAL_OK) { Error_Handler(); }

/* TIM3 interrupt entry, generated file does not define it because
 * TIM3 was not enabled in CubeMX                                   */
void TIM3_IRQHandler(void)
{
    HAL_TIM_IRQHandler(&htim3);
}

连注释都写明了“因为 CubeMX 里没开 TIM3，所以生成文件里没有这个入口”——这行注释本身就是这套做法的解释。注意代码里抢占优先级给的是 1，而 NVIC 表里显示的是 0（因为表里没勾，那个 0 是默认值），以代码为准。

6. 点完 GENERATE CODE 之后，磁盘上发生了什么

这一节你现在就能验证——不用硬件。但先做一件事：确认工程能回退（git status 干净，或先复制一份）。

文件/目录生成时会发生什么能不能手改
Src\main.c注释外全部重写；USER CODE 段保留只能改 USER CODE 段
Src\stm32f4xx_it.c按勾选的中断生成入口函数同上；这也是为什么 TIM3 入口要自己写
Src\stm32f4xx_hal_msp.c外设底层（时钟使能、引脚复用）同上
Inc\stm32f4xx_hal_conf.h只改 HAL_XXX_MODULE_ENABLED 那组宏可以改宏，但重生成可能被还原——这个工程的 HAL_TIM_MODULE_ENABLED 就是被注释过导致 hal_tim.c 变空
MDK-ARM\*.uvprojx按 Toolchain=MDK-ARM 重新生成 Keil 工程不要在 Keil 里手动加的源文件指望它保留，重生成后要回 Keil 补
Src\App\*不动（不是它管的目录）随便改，业务代码都在这
三条“点之前”的红线：① 没有 git 干净状态不点；② 有未保存的 Keil 修改先存；③ 改完 CubeMX 一定要回 Keil 重新编译一次——很多“点了生成就编译不过”都是 hal_conf.h 的宏被还原、或 uvprojx 少加了文件。

8. 硬件到货那天，你要亲手重放一遍

这本手册解决“看得懂”，手感只能在板子上建立。建议按下面的顺序，每一步都有验收标准，不通过不往下走。

步骤动作验收标准（必须能指着看到）
0git checkout -b bringup，复制一份 .ioc分支建好；.ioc 有备份
1打开 CubeMX，加载 .ioc，什么都不改，先照第 3 节把六个区域点一遍能不看手册说出“这个按钮在哪、改了会动哪”
2确认板上晶振丝印（8.000 / 25.000）拍照存证；若是 25MHz，则 PLLM=25 且 HSE_VALUE=25000000
3RCC → Crystal；时钟树 PLL 源拨 HSE、M 改 8生成后 SystemClock_Config 里出现 RCC_OSCILLATORTYPE_HSE、RCC_HSE_ON、RCC_PLLSOURCE_HSE、PLLM=8 四行
4编译 + 烧录能跑；若黑屏先怀疑起振失败，要能改回 HSI 降级（否则 Error_Handler() 的 while(1) 会被误判成烧录失败）
5有示波器：把某根 GPIO 在 TIM3 中断里翻转，量周期1.000ms（±1%）
6没有示波器：打印 HAL_RCC_GetSysClockFreq() 与 PCLK1168000000 与 42000000
顺序不要改。先“只读点一遍”建立手感 → 再“确认晶振” → 才“改配置”。反过来做（先改 HSE 再想怎么验证），一旦起振失败你手上没有任何对照，只会以为是烧录坏了。
